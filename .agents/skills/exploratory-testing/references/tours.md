# Tours for apps with many small controls

Firstmate addition, not upstream.
Tours are a lens for choosing the next charter; the tour idea and several names come from the agentic-qe `exploratory-testing-advanced` skill (MIT) and Whittaker's exploratory-testing tours, and the descriptions here are our own wording; Claims and Saboteur are additions from our own use.
Pair each tour with the upstream charter form and oracles.

| Tour | Do this |
|------|---------|
| FedEx | Follow one piece of data end to end: create it, edit it, save, close, reopen, export, and check every place it shows up. |
| Garbage Collector | Visit the empty, blank, duplicate, deleted and leftover states of every record kind. |
| Rained-Out | Interrupt: cancel, Escape, close, delete or navigate away halfway through an action, and delete the thing that is open in another tab. |
| Couch Potato | Do the minimum: accept every default, leave fields empty, click Next without reading. |
| Obsessive-Compulsive | Repeat: the same action many times, double-clicks, repeated Enter, repeated undo. |
| Back Alley | Use the least-used features: menus, settings, About, keyboard-only paths, right-click menus. |
| Supermodel | Look only at the surface: layout at the smallest and largest window, contrast, truncation, clipped or overlapping text, dark mode. |
| Antisocial | Give hostile input: HTML, entities, emoji, RTL text, very long strings, leading whitespace. |
| Landmark | Hop between the named screens and features by every route, including shortcuts, and check where you land. |
| All-Nighter | Leave it open and keep working: many edits in one session, large content, state that accumulates. |
| Saboteur | Break the environment: offline, slow, a failing backend, low disk, a missing file. |
| Claims | Read every label, tooltip and toast as a promise, then check the app keeps it. |
